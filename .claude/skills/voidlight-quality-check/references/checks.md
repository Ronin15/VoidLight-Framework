## 4. Threading Safety (CLAUDE.md › Performance and Threading; `.claude/rules/managers.md` › Threading)

### 4.1 Non-thread_local static state
```bash
grep -rnE "^\s*static\s" src/ --include="*.cpp" \
  | grep -vE "static_cast|static (const|constexpr|inline)\b|thread_local|static_assert|\(| instance;"
```
Remaining hits (e.g. file-scope `static std::atomic` counters) need a thread-ownership check. BLOCKING if mutable, shared, and touched from worker batches.

### 4.2 Raw threads, private scheduling, WorkerBudget bypass
```bash
grep -rnE "std::(thread|jthread)\b|std::async|\.detach\(\)" src/ include/ \
  | grep -vE "std::thread::id|this_thread|include/core/ThreadSystem.hpp"
grep -rn "hardware_concurrency" src/ include/ | grep -v "ThreadSystem\|WorkerBudget"
```
For new batch work also confirm: `WorkerBudget` decides thread/batch shape, execution is reported after completion, futures complete before dependent work. BLOCKING.

### 4.3 Synchronization matches ownership (review)
No blanket "every manager needs a mutex" rule — main-thread-only managers (UI, input, state stack) need none. Check that state touched from worker batches is thread-local, partitioned by batch range, atomic, or locked; hot contended atomics use `alignas(64)`. Do not add locks to defend races that cannot occur — see `docs/review-non-issues.md` §B.

## 5. Architecture Compliance

### 5.1 GPU frame lifecycle (CLAUDE.md › Rendering, UI, and GameState)
```bash
grep -rnE "endFrame|beginFrame|present\(|SubmitGPU|AcquireGPUSwapchain|SDL_RenderPresent|SDL_RenderClear" \
  src/gameStates/ src/controllers/ --include="*.cpp"
```
States implement `recordGPUSceneVertices()` / `recordGPUUIVertices()` / `renderGPUScene()` / `renderGPUUI()` only. Any hit is BLOCKING.

### 5.2 RAII and ownership (CLAUDE.md › C++ and APIs)
```bash
grep -rnE "\bnew [A-Z]\w*[({]" src/ include/ | grep -vE "^\S+:\s*(//|\*)"
grep -rnE "\bdelete\b" src/ include/ --include=*.cpp --include=*.hpp | grep -vE "= delete|//|\*"
grep -rnE "[A-Z]\w*\*\s*\w+\s*=\s*nullptr\s*[,)]" include/        # nullable raw-pointer params
```
Raw-pointer ownership: BLOCKING. New nullable raw-pointer params/returns/out-params: WARNING (existing optional-lookup contracts in `.claude/rules/managers.md` excepted). `.get()` belongs only at the final GPU/SDL API boundary.

### 5.3 shared_ptr in hot paths
```bash
grep -rn "auto.*=.*shared_ptr" src/ | grep -v "\.get()\|make_shared"
grep -rn "for.*EntityPtr\|for.*shared_ptr<" src/
```
Flag copies (atomic ref-count) or by-value lambda captures of `shared_ptr` inside batch/update paths; pass `const&` or iterate EDM indices/handles instead. Context: commit a8aa267e. BLOCKING in perf-critical code.

### 5.4 string_view → string churn (CLAUDE.md › C++ and APIs)
```bash
grep -rnE "std::string \w+Str\(" src/ --include="*.cpp"
grep -rnE "std::string\([a-z]\w*\)" src/ --include="*.cpp" | grep -i "find\|\[\|at("
```
A `string_view` param converted to `std::string` for a map lookup is a regression — use `const std::string&`. BLOCKING on hot paths.

### 5.5 Logging (CLAUDE.md › C++ and APIs)
Macros are subsystem-specific (`AI_INFO`, `GAMEENGINE_WARN`, … or `VOIDLIGHT_INFO(system, msg)`), with `*_IF` variants; all in `include/core/Logger.hpp`.
```bash
grep -rnE "std::(cout|cerr)|\bprintf\(" src/ | grep -v "//"
grep -rnE "(INFO|DEBUG|WARN|ERROR)(_IF)?\(.*(\" \+|\+ \")" src/
grep -rnE "#if(def)? *(defined\()?DEBUG" src/ include/ | grep -v "include/core/Logger.hpp"
```
Conditional-only logging (`if (x) { AI_INFO(...); }`) should be `AI_INFO_IF(x, ...)` — eyeball during review. WARNING.

### 5.6 Per-frame allocations (CLAUDE.md › Performance and Threading)
```bash
grep -rn "std::vector<.*>" src/ --include="*.cpp" | grep -E "update|render|process" | grep -v "m_"
```
Local containers or `make_unique/make_shared` in update/render/batch paths → reuse a member (or `thread_local` in worker code) and `clear()`. Missing `reserve()` when size is known is a WARNING. BLOCKING on hot paths.

### 5.7 UI positioning (CLAUDE.md › Rendering, UI, and GameState; `.claude/rules/ui-controllers.md`)
Helpers (`createTitleAtTop`, `createButtonAtBottom`, `createCenteredButton`, `createCenteredDialog`, `create*AtBottomRight`) position themselves. Flag files where plain creates outnumber positioning calls, then eyeball:
```bash
for f in src/gameStates/*.cpp src/controllers/ui/*.cpp; do
  c=$(grep -E "\.create[A-Z][A-Za-z]*\(" "$f" | grep -vcE "AtTop\(|AtBottom\(|AtBottomRight\(|createCentered")
  p=$(grep -c "setComponentPositioning" "$f")
  [ "$c" -gt "$p" ] && echo "$(basename "$f"): create=$c positioning=$p"
done
grep -rn "GameEngine::Instance" src/controllers/      # controllers must use UIManager sizing/relayout APIs
```
WARNING.

### 5.8 Transitions and loading (CLAUDE.md › Rendering, UI, and GameState)
```bash
grep -rnE "changeState|pushState" src/gameStates/ --include="*.cpp"   # confirm none execute inside ::enter()
grep -rnE "(while|for).*(render|recordGPU)" src/gameStates/ --include="*.cpp"
```
Transitions use `mp_stateManager->changeState(GameStateId::...)` from `update()`; loading uses `LoadingState` + `ThreadSystem`, never a blocking render loop. BLOCKING.

### 5.9 Singleton access (CLAUDE.md › Rendering, UI, and GameState)
```bash
grep -rnE "mp_\w*(Mgr|Manager|edm|world|ui|particle|event)" include/gameStates/ | grep -v mp_stateManager
for f in src/gameStates/*.cpp; do awk '/^(void|bool) .*::/{fn=$2; sub(/\(.*/,"",fn); delete s}
  /::Instance\(\)/{m=$0; sub(/.*&[[:space:]]*/,"",m); sub(/[[:space:]]*=.*/,"",m); if (s[m]++) print FILENAME": dup in "fn": "m}' "$f"; done
```
Cached manager `mp_*` members: BLOCKING (`mp_stateManager` is the sanctioned exception). Duplicate `Instance()` hits may be in separate scopes — confirm before flagging (WARNING).

### 5.10 Controller access (CLAUDE.md › Rendering, UI, and GameState)
```bash
grep -rn "mp_\w*Ctrl" include/gameStates/
for f in src/gameStates/*.cpp; do awk '/^(void|bool) .*::/{fn=$2; sub(/\(.*/,"",fn); delete s}
  /m_controllers\.get</{c=$0; sub(/.*get</,"",c); sub(/>.*/,"",c); if (s[c]++) print FILENAME": dup in "fn": "c}' "$f"; done
```
Controllers are added with `m_controllers.add<T>()` in `enter()`; no cached `mp_*Ctrl` (BLOCKING). Cache `*m_controllers.get<T>()` in a local only when used more than once in a scope.

### 5.11 Behavior per-entity state (CLAUDE.md › EDM, AI, and Controllers; `.claude/rules/ai.md`)
Behaviors are `Behaviors::` executor functions in `src/ai/behaviors/*.cpp` taking `BehaviorContext` plus a config and EDM variant state (`include/ai/BehaviorStateData.hpp`, e.g. `GuardStateData`). There is no per-behavior class instance to hold state.
```bash
grep -nE "^\s*(static\s+)?[A-Za-z_:<>]+\s+[gs]_\w+" src/ai/behaviors/*.cpp src/ai/BehaviorExecutors.cpp | grep -v thread_local
grep -rnE "(GameTimeManager|WeatherController|WorldManager)::Instance" src/ai/behaviors/ src/ai/BehaviorExecutors.cpp
```
Cross-frame per-entity state (targets, timers, counters, paths) belongs in EDM behavior/path state; new fields go in the variant `*StateData` (or shared `BehaviorData` only if truly shared). Executors read cached `ctx` data (`ctx.envSnapshot`, player/world bounds) instead of calling main-thread services. Transitions go through `Behaviors::switchBehavior()`; state is initialized after commit. Known OK: the main-thread-written `s_cachedBounds` world-bounds cache in `BehaviorExecutors.cpp`. BLOCKING.

### 5.12 Controller → AI boundary (CLAUDE.md › EDM, AI, and Controllers)
```bash
grep -rnE "get(Guard|Flee|Attack|Chase|Wander|Patrol|Follow|Idle)State\(|\.alertLevel|\.hasActiveThreat" src/controllers/ --include="*.cpp"
grep -rn "queueBehaviorMessage\|deferBehaviorMessage" src/controllers/ --include="*.cpp"
```
Controllers send `Behaviors::queueBehaviorMessage(idx, BehaviorMessage::...)` (main thread); workers use `deferBehaviorMessage`. Reference: `SocialController::alertNearbyGuards` (`AIManager::scanGuardsInRadius` + `RAISE_ALERT`). Direct mutation: BLOCKING.

### 5.13 State-transition completeness (CLAUDE.md › State Transitions and Events)
```bash
for f in $(grep -rln "AIManager::Instance" src/gameStates/ --include="*.cpp"); do
  echo "== $f"; grep -nE "prepareForStateTransition|m_controllers\.clear\(\)" "$f"; done
```

Compare each exit path (to-loading and full exit) against the 11-manager order in CLAUDE.md; AIDemo/EventDemo may skip managers they never initialized. `GamePlayState::exit()` must call `m_controllers.clear()` (not just `unsubscribeAll()`). `GamePlayState.cpp` is the reference implementation. ### 5.14 Thread-local capacity (CLAUDE.md › Performance and Threading)
```bash
grep -rnE "\.swap\(t_|t_\w+\.swap\(|std::swap\([^)]*t_" src/ --include="*.cpp"
grep -rnE "return (std::move\()?t_\w+\)?;" src/ --include="*.cpp"
```
Collect via `void collect(std::vector<T>& out)` + `t_buf.clear()`. Note `EventManager::enqueueBatch(std::move(m_allDamageEvents))` is an adjudicated non-issue. BLOCKING.

### 5.15 World-lifecycle cleanup (CLAUDE.md › State Transitions and Events; `.claude/rules/managers.md` › Lifecycle)
```bash
grep -rln "WorldUnloaded\|WorldLoaded" src/managers/ --include="*.cpp"
grep -rnE "m_\w*(Index|Lookup|Cache)\b" include/managers/ --include="*.hpp"
```
World-geometry caches, spatial indices, reverse lookups, and cached EDM indices must be cleared by transition cleanup or unload handling — not only by a later deferred event. `WorldUnloaded` is dispatched Immediate by design. BLOCKING.

### 5.16–5.19 Review-only (WARNING)
No reliable grep; check during diff review.
- **5.16 Second source of truth** — per-entity state that render, collision, save/load, or the next frame reads must live in EDM, not manager/controller scratch (`.claude/rules/ui-controllers.md`: controllers are never a second source of truth). Starting point: `grep -rn "unordered_map<EntityHandle" include/managers/ include/controllers/`.
- **5.17 Render-controller lifecycle** — `src/controllers/render/` reads state and emits draws; no `prepareForStateTransition`, manager `clear*`, or unsubscribing others' handlers: `grep -rnE "prepareForStateTransition|unsubscribe|Instance\(\)\.(clear|remove|destroy)" src/controllers/render/`.
- **5.18 Event-contract bypass** — if existing writers of a field fire an event (UI refresh, log, collision), new writers must fire the same event with the same immediate/deferred dispatch.
- **5.19 EDM policy creep** — EDM stores facts/state; thresholds, weights, emotion math, and decision policy belong in AI/behavior code (`.claude/rules/managers.md` › EntityDataManager Contracts). Starting point: `grep -nE "Threshold|Weight|Multiplier|Tuning|Decision" include/managers/EntityDataManager.hpp`.

### 5.20 Event handler & collision-callback ownership (CLAUDE.md › State Transitions and Events)
```bash
grep -rn "registerPersistentHandler\|clearAllHandlers" src/gameStates/ src/controllers/
grep -rnE "subscribeWorldEvents|[cC]ollision\w*\.(register|subscribe|set\w*Callback|add\w*Callback)" src/gameStates/
```
Managers register persistent handlers in `init()`; states/controllers register transient handlers in `enter()` (controllers via `ControllerBase` tokens). No manual unsubscribe/resubscribe of persistent handlers across transitions; `clearAllHandlers()` is shutdown-only; states never register collision callbacks. WARNING (BLOCKING if a persistent handler is lost or duplicated across transitions).
